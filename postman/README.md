# Postman collection

A Postman collection covering the local daemon's HTTP API: **368 requests in 28
folders**, built from the route definitions in `design/apps/daemon/`.

> [!IMPORTANT]
> **No request in this collection has been sent.** The collection was generated by
> reading route definitions out of the vendored source — no daemon was started,
> no response was observed, and no response example is recorded. Methods, paths
> and path parameters are accurate transcriptions of the registered routes.
> Request bodies are derived from what each handler reads off `req.body` and from
> the shared DTOs in `design/packages/contracts/src/api/`, but they are
> **unverified examples**, not a proven wire format. See
> [Honesty and drift](#honesty-and-drift).

## Files in this category

| File | What it covers |
| --- | --- |
| [material-designer-daemon.postman_collection.json](material-designer-daemon.postman_collection.json) | The collection itself: Postman Collection v2.1.0, one folder per capability area, `{{baseUrl}}` variable, path parameters as Postman variables, JSON example bodies on every write request. |

There is no environment file. The collection needs exactly one variable and
carries it as a collection variable, so importing the single JSON file is
sufficient. Do not add an environment file containing a token value — see
[Security](#security).

## Importing it

Postman's **Import** button accepts the file directly.

1. **Import → File → Upload Files**, and choose
   `postman/material-designer-daemon.postman_collection.json`.
2. Postman detects the v2.1.0 schema and creates a collection named
   **Material Designer — daemon API**.
3. The `baseUrl` variable arrives with it, already set to
   `http://127.0.0.1:7456`.

The Postman CLI and Newman read the same file:

```bash
newman run postman/material-designer-daemon.postman_collection.json \
  --folder 'Health & daemon' \
  --env-var baseUrl=http://127.0.0.1:7456
```

Running the whole collection unattended is a bad idea: it contains project
deletion, database vacuum and daemon shutdown. See
[Destructive requests](#destructive-requests).

## Getting a daemon to talk to

The collection is inert without a running daemon. The daemon is
`design/apps/daemon` and is started through the workspace's lifecycle tool, not
directly:

```bash
cd design
pnpm install
pnpm tools-dev run web --daemon-port 7456 --web-port 7573
```

`pnpm tools-dev` is the only supported local lifecycle entry point in that
workspace — there is deliberately no root `pnpm dev` or `pnpm start`. Full
prerequisites (Node `~24`, `pnpm@10.33.2`, and the native-module build
requirements on Windows) are in
[../docs/build/from-source.md](../docs/build/from-source.md).

Confirm it is up before working through a folder:

```bash
curl -sf http://127.0.0.1:7456/api/health
curl -sf http://127.0.0.1:7456/api/ready
curl -sf http://127.0.0.1:7456/api/daemon/status
```

## Base URL and how to change it

Every request is built as `{{baseUrl}}` plus its path. Change the variable in one
place and the whole collection follows.

| Property | Value | Override |
| --- | --- | --- |
| `baseUrl` collection variable | `http://127.0.0.1:7456` | Edit it in **Collection → Variables**, or pass `--env-var baseUrl=…` to Newman. |
| Daemon port | `7456` | `OD_PORT`, or `--port` |
| Daemon bind address | `127.0.0.1` | `OD_BIND_HOST`, or `--host` |

If you start the daemon on another port, change `baseUrl` to match — do not edit
individual requests.

## Loopback binding, and what it means for you

**The daemon binds `127.0.0.1` by default.** It is a local, single-user service:
there is no account model, no per-request signature, and no tenancy. The controls
that exist are the bind address and an origin guard sitting in front of the whole
`/api` tree.

That has three consequences for anyone using this collection.

**It only answers from the same machine.** A `baseUrl` pointing at another host
will not connect unless somebody has deliberately rebound the daemon. If you find
yourself reaching for a LAN address, stop and read the paragraph below first.

**A number of endpoints check more than the bind address.** Handlers marked
*loopback-only*, *local-daemon only* or *local-same-origin only* in their
descriptions run an additional guard and refuse the request when the daemon is
bound to a non-loopback address — the connector, live-artifact, library,
BYOK-credential, diagnostics-export and daemon-control routes among them. A
request that works on loopback and 403s elsewhere is that guard doing its job,
not a bug in the collection.

**Exposing it is equivalent to granting shell access.** The API's purpose is
running locally installed agent tools with your privileges; the terminal folder
streams stdin and stdout to a real shell process. Binding it to a routable
address additionally requires `OD_ALLOWED_ORIGINS`, and the containerised
deployment requires an `OD_API_TOKEN` shared secret. Those are two deliberate
acts, and they are deliberate for a reason.

## Streaming endpoints

**17 endpoints stream Server-Sent Events.** Each is marked `SSE stream.` at the
start of its description and carries an `Accept: text/event-stream` header.

| Endpoint | What it streams |
| --- | --- |
| `GET /api/projects/:id/events` | `ready` and `file-changed` events for a project. |
| `POST /api/chat` | Run events for the legacy single-call chat entry point. |
| `GET /api/runs/:id/events` | An agent run's event log plus live events; resumable via `Last-Event-ID`. |
| `GET /api/runs/:id/agui` | The same run events re-encoded into the AG-UI protocol. |
| `GET /api/projects/:id/terminals/:tid/stream` | PTY `data` and `exit` events, with `Last-Event-ID` replay. |
| `GET /api/library/events` | `ready`, then `ingest` and `delete` events. |
| `GET /api/memory/events` | `connected`, then `change`, `extraction` and `verify` events. |
| `GET /api/plugins/events` | Backlog since `?since=`, then live plugin events. |
| `POST /api/plugins/install`, `POST /api/plugins/:id/upgrade` | Install and upgrade progress, success and error events. |
| `POST /api/proxy/{anthropic,openai,azure,google,ollama,senseaudio,aihubmix}/stream` | Re-emitted `start`/`delta`/`end`/`error` frames from the upstream BYOK provider. |

`GET /api/agents` is a hybrid: it returns ordinary JSON, and becomes an SSE
stream only when called with `?stream=1`. The query parameter ships disabled on
that request.

**Postman does not close a stream for you.** It renders incoming frames in the
response pane as they arrive and leaves the request running until you press
**Cancel**. That is expected behaviour, not a hang — but it means a streaming
request left open holds a daemon connection, and that Newman will sit on one
forever. Exclude the streaming folders from unattended runs, or use `curl -N`
when you want a stream you can `Ctrl-C`:

```bash
curl -N -H 'Accept: text/event-stream' \
  http://127.0.0.1:7456/api/runs/run_3/events
```

## Destructive requests

**43 requests are marked `[destructive]` in their name** and carry a warning in
their description. Every `DELETE` is marked, plus the writes that remove,
overwrite or externally publish state without an undo.

The ones worth knowing before you click anything:

| Request | What it does |
| --- | --- |
| `POST /api/daemon/shutdown` | Stops the daemon. Everything else in the collection stops working. |
| `POST /api/daemon/db/vacuum` | Rewrites the SQLite database file in place. |
| `DELETE /api/projects/:id` | Cancels live runs, deletes the row **and removes the project directory**. |
| `POST /api/projects/:id/working-dir` | Rebinds an existing project to a different directory and clears its saved tabs. |
| `DELETE /api/memory/extractions`, `DELETE /api/memory/verifications` | Clear the entire history, not one record. |
| `POST /api/projects/:id/deploy` | Publishes to Vercel or Cloudflare Pages — a public, external side effect. |
| `POST /api/projects/:id/plugins/publish-github`, `…/contribute-open-design` | Push a repository and open a pull request against a public project. |

The local version-history routes under **Project files & versions** are the undo
path for file edits. There is no equivalent for project deletion.

## Security

- **Never commit a token, API key or credential into this collection.** Several
  bodies carry an `apiKey`, `token` or `credentials` field with the literal
  placeholder `REPLACE_ME`. Substitute values at run time through a Postman
  environment or `--env-var`; keep the values out of version control.
- **The BYOK proxy folder sends your key to a third party.** Those requests hand
  `apiKey` to the daemon, which forwards it to the named provider. That is the
  feature, but it means a saved value leaves your machine.
- **The terminal folder is a real shell.** `POST …/terminals/:tid/stdin` writes
  bytes to a live process running as you.
- **The proxy routes block private address space** — link-local, carrier-grade
  NAT and cloud-metadata ranges included. `OD_ALLOWED_INTERNAL_HOSTS` opts a
  named host out and re-enables a class of server-side request forgery for that
  host.
- **Do not point `baseUrl` at somebody else's daemon.** Reaching this API is
  reaching their machine.

## Honesty and drift

**This collection is generated by reading route definitions, not by observing a
running daemon.** Three things follow from that, and all three are worth stating
plainly.

**It can drift.** The collection is a snapshot of the routes as they were read.
Nothing in the build enforces that it stays in step, so a route added, renamed or
removed in `design/apps/daemon/` leaves the collection stale and nothing will
say so. Treat a mismatch between this file and the source as the collection being
wrong.

**Bodies are derived, not proven.** Each example body was built from the fields a
handler actually reads and from the shared DTOs in
`design/packages/contracts/src/api/`. Where a handler's expectations were not
clear from the source, the body was kept minimal rather than padded with invented
fields — so an example may be *incomplete*, but it should not contain a field
that does not exist. Optional fields are frequently omitted.

**No responses are recorded.** Every request has an empty `response` array. The
repository's API documentation asks that requests be exercised against a live
daemon before their shapes are treated as fact; that has not happened, and this
file does not claim otherwise. See
[../docs/api/README.md](../docs/api/README.md) for the standing rule.

### Regenerating and verifying

The route surface is enumerated directly from the source. To re-derive it:

```bash
# String-literal registrations — the large majority.
grep -rEn "\b(app|router)\.(get|post|put|patch|delete|all|options)\(\s*['\"\`]/" \
  design/apps/daemon/src --include='*.ts'
```

Four other registration styles exist and a naive grep misses all of them. Each
must be checked separately:

| Style | Where | How to find it |
| --- | --- | --- |
| `RegExp` literal routes | `routes/project/index.ts` | `grep -rn "app\.\(get\|post\|delete\|options\)(/\^" design/apps/daemon/src` |
| Path passed to a registrar helper | `routes/chat.ts` (`registerByokToolChatProxy`) | `grep -rn "register[A-Za-z]*(\s*'/api/" design/apps/daemon/src` |
| Imported path constant | `routes/attribution.ts`, `server.ts` | `grep -rn "_PATH = ['\"]/api/" design/packages` — the constant is defined in a package and the daemon registers it by name, sometimes on the line after `app.get(` |
| Route descriptor objects | `routes/active-context.ts` (`mountJsonRoute`) | `grep -rn "path: *'/api/" design/apps/daemon/src` |

To check the collection against that inventory, compare the method-and-path pairs
in the JSON with the grep results:

```bash
python3 - <<'PY'
import json
c = json.load(open('postman/material-designer-daemon.postman_collection.json'))
for folder in c['item']:
    for item in folder['item']:
        r = item['request']
        print(r['method'], r['url']['raw'].replace('{{baseUrl}}', '').split('?')[0])
PY
```

Validating that the file is well-formed is one command:

```bash
python3 -c "import json; json.load(open('postman/material-designer-daemon.postman_collection.json')); print('ok')"
```

Two CORS preflight handlers — `OPTIONS /api/projects/:id/raw/*splat` and
`OPTIONS /api/projects/:id/powered/*splat` — are deliberately absent. They carry
no payload and Postman issues preflights itself. Every other registered endpoint
is present.
